# Project instructions

## Spelling

Always use American English spellings. This applies everywhere: markdown cells,
code comments, docstrings, identifiers and variable names, string literals, UI
and log text, notebook prose, README content, and commit messages.

Prefer the American form:

| Use | Not |
| --- | --- |
| analyze, analyzed, analyzing | analyse, analysed, analysing |
| behavior, behavioral | behaviour, behavioural |
| canceled, canceling | cancelled, cancelling |
| catalog | catalogue |
| center, centered | centre, centred |
| color, colored | colour, coloured |
| customize, customization | customise, customisation |
| defense, offense, license (noun) | defence, offence, licence |
| favorite | favourite |
| gray | grey |
| initialize, initialization | initialise, initialisation |
| judgment | judgement |
| labeled, labeling | labelled, labelling |
| modeled, modeling | modelled, modelling |
| normalize, normalization | normalise, normalisation |
| optimize, optimization | optimise, optimisation |
| organize, organization | organise, organisation |
| program | programme |
| recognize | recognise |
| serialize, tokenize, vectorize | serialise, tokenise, vectorise |
| summarize, summarization | summarise, summarisation |
| visualize, visualization | visualise, visualisation |
| while | whilst |

The general rules: `-ize`/`-ization` over `-ise`/`-isation`, `-or` over `-our`,
`-er` over `-re`, and a single `l` before a suffix (`modeling`, not
`modelling`).

Two exceptions:

1. An external API or library dictates the spelling. Mirror those exactly and do
   not "fix" them.
2. Captured program output already stored in a notebook. Cell outputs are a
   record of what the tool actually printed, so leave their wording alone even
   when it is British (for example, pip's "This behaviour is the source of the
   following dependency conflicts").

## Prose style

Course content is authored by a human instructor and should read that way. Avoid
em-dashes and avoid "not x, it's y" constructions.
